## 1. MVP 功能按用户行为理解

| 功能 | 什么时候用 | 当前责任边界 | 验证重点 |
|---|---|---|---|
| 能力授权与 scope | Agent 请求工具/MCP | Security 决定，Runtime 在工具前执行 | 未授权零执行；命令组合不被误判为安全单命令 |
| 人工确认 | normal 下操作需要用户同意 | Runtime HITL 与 Security 确认/会话信任配合 | 审批目标对应，拒绝/超时不能继续 |
| DLP | normal 下内容进入模型、工具或发布出口 | Security 给出 findings/action，Runtime 应用到真实载荷 | block 零外发；mask 发布脱敏值；历史与输出都覆盖 |
| Token | 模型使用及会话预算 | Security 计量与预算，Runtime 控制 Run | 按正确 Agent/Session 累加；不能只按 Agent 汇总判断会话配额 |
| 网络策略 | Worker 外连 | Security 策略，Runtime/系统执行约束及观测 | 实际网络结果、effective/apply 状态、事件三者一致 |
| syscall | Worker 执行危险系统调用 | seccomp 阻断，采集器送审计 | 内核 errno + 身份完整的事件；不能仅靠 Python 异常 |
| 沙箱与资源约束 | 创建执行实例 | Security 选策略，Runtime 建 host/bwrap 实例 | 实际 PID/cgroup/ns、资源与退出回收 |
| 审计 | 决策、配置变更、执行事件 | Security 存储、查询和完整性校验 | 来源、身份和决定可关联，链可验证 |
| 签名/manifest | 安装及受信启动 | 校验实现保留；当前 demo 包有明确配置选择 | demo 与生产配置区分，不把自签测试当组织信任 |
| normal/YOLO | 管理员按 Agent 切换 | securityd 持久化权威模式 | 切换后的有效策略和 Worker 状态一致 |

## 2. 当前 normal / YOLO 的准确语义

这是本基线最需要口头说明的部分。早期文档和 9 月 15 日某些专项报告使用过旧语义；当前应按下表维护。

**当前新注册 Agent 的初始模式为 YOLO。** `capability_registry.py::_ensure_initial_security_mode_locked` 使用 `INSERT OR IGNORE` 初始化，保留已有管理员选择。不能假定新建 Agent 自动处于 normal；做权限/DLP 拒绝验收前必须显式读取并设为 normal，测试结束恢复原值。

| 行为 | normal | YOLO |
|---|---|---|
| capability/scope | ALLOW / CONFIRM / DENY | 放行，包括未映射能力场景的相应适配 |
| 权限 HITL | 需要确认时触发 | 不因能力授权触发 |
| DLP | 按配置扫描、mask/block 等 | 跳过扫描与阻断，记录 bypass/skip 语义 |
| 网络限制 | 按保存策略及后端实际执行 | 有效模式为 allow_all，保留被动观测 |
| Token 配额 | 会话/日预算参与控制 | 有效上限为 0（不限），用量继续累计 |
| 调用者、Worker lease 身份 | 保留 | 保留 |
| 沙箱、syscall/进程约束 | 按执行策略 | 不因 YOLO 自动解除 |
| 审计/用量记录 | 保留 | 保留相关记录与模式标记 |
| normal 原配置 | 生效 | 保留，不覆盖为“无限/全允许” |

切回 normal 后使用原策略及累计用量。模式不是本地缓存的永久放行证；读取失败不能自行假定 YOLO。正常的业务拒绝、数据错误、传输不可用也不能全部归为一种异常。

模式切换可能需要 Worker 重启：当前 Security 对活动 bwrap 实例直接改模式会拒绝并要求重启；Runtime 管理链路负责协调。不能承诺所有后端“点一下立即无损切换”。

源码依据：S `securityd/engine.py` 的 `set_agent_security_mode`、`get_token_budget`、`_effective_network_policy`（均位于 `impl/bianbu-securityd/` 下），S `securityd/uds_handlers.py::dlp_scan`，R `security/security_dlp.py::dlp_checks_disabled`（位于 `bianbu_agent/` 下）。YOLO bypass 审计在部分路径上捕获异常并记录日志，不应将“保留审计”误写成“审计写失败时所有 YOLO 请求必然阻断”。

## 3. D-Bus 控制面

| 项 | 值 |
|---|---|
| 总线服务名 | `io.bianbu.Security` |
| 安全对象/接口 | `/io/bianbu/Security` / `io.bianbu.Security` |
| Runtime 策略对象/接口 | `/io/bianbu/Security/Runtime` / `io.bianbu.Security.Runtime` |
| 正式部署总线 | system bus |
| 独立开发会话 | session bus，调用方和服务必须使用同一地址 |

下表列维护时常用的方法族，不替代精确参数契约。

| 方法族 | 代表方法 | 使用者/注意事项 |
|---|---|---|
| Agent 注册/能力 | `RegisterAgent`、`SyncAgentCapabilities`、`GetCapabilities`、`SetCapabilityGranted` | 控制面；同步能力不得顺便覆盖安全模式 |
| 判权/确认 | `CheckPermissionV2`、`RequestConfirmV2`、`GrantSessionTrustV2` | 关注 Session 上下文、调用者权限 |
| 模式 | `GetAgentSecurityMode`、`SetAgentSecurityMode` | 管理动作，记录 actor 和模式转换 |
| Token | `GetTokenBudgetV2`、`SetTokenBudget`、`MeterTokensV2` | 配置、读取与计量分清；V2 保留会话粒度 |
| 网络 | `SetNetworkPolicy`、`GetNetworkPolicy`、`GetNetworkLearningEvents` | 写入成功不等于所有实例执行成功 |
| syscall | `GetSyscallPolicy`、`GetSecurityExecutionStatus`、`GetSyscallAuditEvents` | 关注策略版本与 pending restart |
| DLP 配置 | `SetDLPPolicy`、`DeleteDLPPolicy` | 数据扫描通过 UDS；不要在 Worker 开放管理写权限 |
| 审计 | `ExportAudit`、`VerifyAuditChain` | 读取与校验原始证据 |
| 启动事务 | `PrepareStart`、`GetSandboxPolicy`、`CommitStart`、`AbortStart` | 控制进程先授权再启动，再核验提交 |
| 实例生命周期 | `StopInstance`、`RevokeAgent`、`GetRuntimeState`、`ListRuntimeInstances` | 停止单实例与撤销整个 Agent 的作用范围不同 |

现场查精确签名：

```bash
busctl --system introspect io.bianbu.Security /io/bianbu/Security io.bianbu.Security
busctl --system introspect io.bianbu.Security /io/bianbu/Security/Runtime io.bianbu.Security.Runtime
```

源码入口为 [service.py](../../impl/bianbu-securityd/securityd/service.py)、[D-Bus XML](../../impl/bianbu-securityd/data/io.bianbu.Security.xml) 和 [共用客户端](../../impl/bianbu-securityd/client/bianbu_security_client.py)。新增参数要同时修改三者及 Runtime 调用方。接口名与进程名解耦，不因改服务进程名而换命名空间。

## 4. UDS 数据面

正式 socket 为 `/run/bianbu/securityd.sock`，开发/测试可通过 `BIANBU_SEC_UDS` 指向隔离实例。应使用共用客户端，不在业务代码中手写 framing。

| 动作名 | 作用 |
|---|---|
| `ping` | 连通性；不能证明业务身份授权 |
| `permission.check` | Worker 能力判定 |
| `confirm.request`、`session.trust` | 确认/会话信任 |
| `dlp.policy`、`dlp.scan` | 当前有效 DLP 配置与扫描 |
| `token.budget`、`token.meter` | 预算与用量 |
| `security.mode`、`capabilities.list` | 当前 Agent 模式/能力 |
| `worker.identity` | 受验证 Worker 身份视图 |
| `audit.log`、`audit.batch` | 单条/批量审计 |

Worker 请求带逻辑 `agent_id`，以及 `_worker_security_agent_id`、`_worker_instance_id`、`_worker_lease_id` 等内部身份字段。服务端再读取 SO_PEERCRED 的 PID/UID 和实际 cgroup，验证已提交 lease。知道 ID 字符串不等于有权限。

normal DLP 响应包含 `findings`、`masked_text`、`effective_policy`、`audit_seq` 等；findings 返回类型、位置、风险和 action，不额外复制原始 PII 值。动作包括 `allow`、`audit_only`、`mask`、`block`；非法动作和扫描失败不能默认允许。YOLO 响应有 `mode=yolo`、`scanning_enabled=false`。

## 5. 接口修改检查表

1. 写清发起方、逻辑身份、传输、管理权限和副作用。
2. 同步服务端、客户端、Runtime 适配与 UI/operation（若涉及）。
3. 为未授权、旧 lease、空字段、超长载荷及兼容旧调用补测试。
4. 先做本地/隔离验证，再重启目标服务验证新接口已加载。
5. 记录两仓提交和安装包组合；新硬协议依赖才评估提高最低版本。
