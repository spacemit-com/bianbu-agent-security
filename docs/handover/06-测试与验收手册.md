## 1. 怎样选择测试

| 改动 | 最小验证层次 | 必要的真实行为证据 |
|---|---|---|
| 判权/映射/审批 | 两仓定向单测 + testkit 相关项 | 拒绝时工具零执行；批准后按目标恢复 |
| DLP | scanner/policy + Runtime 模型/工具边界 + 真实 Run | 假敏感样本 block 不外发，mask 后原文不出现在出口 |
| 启动/lease/沙箱 | Security runtime + Runtime execution 测试 + Worker 启动 | PID/cgroup/lease 一致，失败清理，错误身份拒绝 |
| 网络/syscall | 策略/API/采集测试 + 目标内核实测 | 实际网络/内核结果和审计身份对应 |
| Token/模式 | 预算、Agent 上下文、模式切换测试 | 会话粒度、YOLO 用量保留、normal 恢复 |
| 打包/安装 | 完整源码回归 + DEB 安装 smoke | 新进程、新包、manifest、数据升级和新 Run |
| 文档整理 | 路径、命令、链接与一致性检查 | 不需要重启产品服务 |

## 2. Security 测试命令

在具备 pytest、dbus-python、PyGObject 等依赖的验证环境，进入完整 Security checkout。以下不代表本次交接文档已执行这些测试。

```bash
cd impl/bianbu-securityd
python3 -m pytest tests/ --ignore=tests/e2e --import-mode=importlib -q
```

独立 E2E 使用私有会话与数据目录，避免误用在线服务：

```bash
(
  set -eu
  task_e2e_root=$(mktemp -d /var/tmp/bnsec-e2e.XXXXXX)
  trap 'rm -rf "$task_e2e_root"' EXIT
  dbus-run-session -- env     BIANBU_E2E=1 BIANBU_SEC_ROOT="$task_e2e_root"     BIANBU_SEC_UDS="$task_e2e_root/run/bianbu/securityd.sock"     PYTHONPATH="$PWD:$PWD/client"     python3 -m pytest tests/e2e --import-mode=importlib -q
)
```

验收：两条命令退出 0；E2E 真正收集和执行用例，无 skipped。当前源代码有 3 个专用 E2E 用例，新增测试后按新集合记录，不冻结通过数。lease 定向入口为 `tests/unit/test_runtime_lease.py`、`test_runtime_engine.py`、`test_runtime_policy.py`。

## 3. Runtime 定向测试起点

从 R 根目录执行，依赖按 Runtime 锁文件安装：

```bash
uv run pytest -q   tests/runtime/test_security_runtime.py   tests/runtime/test_execution_runtime.py   tests/runtime/test_security_uds_transport.py   tests/runtime/test_security_tool_mapping.py   tests/test_security_middleware.py   tests/test_security_dlp_enforcement.py   tests/test_model_dlp_boundary.py   tests/runtime/test_security_mode_worker_transition.py
```

这是建议的跨边界定向组，不是完整 Runtime 测试全集。网络、syscall、API 或安装改动时再增加相应组；完整回归入口为 `uv run pytest -q`。

旧资料里“73 failed”属于历史环境结果，不能直接豁免今天的失败。发现失败时，使用同机、同解释器、同配置、同一测试集合对照修改前后，保存 exit code 与逐项失败集合。必要时对比启用/关闭安全的实验结果，但正式交接必须回到启用安全的真实运行链路。

## 4. testkit 端到端

唯一操作入口为 [testkit README](../../testkit/README.md)。在配置好真实 Runtime/securityd 的 Worker：

```bash
cd /home/bianbu/bnsec-testkit
python3 runner.py
# 单项定位示例
python3 runner.py CAP-01 SCOPE-01 HOOK-03 ERR-01
```

本次对 `tests_all.py` 做静态核对，当前注册 **37 项**；这是用例数量，不是本次执行通过数。

不要执行 `engine.py`，它可能使用另一模块实例而显示 0 项。退出码：0 为全部通过，1 为失败/错误，2 为用例 ID 错误。归档 `report.json`、运行日志和审计差分。

若用安装包验证，至少核对下列配置，不能复制历史 Agent ID：

| 配置 | 应指向 |
|---|---|
| `PA_ROOT` | 与安装包相符的 Runtime 源码 |
| `BNSEC_SECURITY_PLUGIN_ROOT` | `/usr/share/bianbu-agent-runtime/plugins/bianbu.security` |
| `BIANBU_SECURITYD_HOME` | `/usr/lib/bianbu-securityd` |
| `PA_AGENT_ID` | 本次测试 Session 的实际逻辑 Agent |
| `BIANBU_PA_AGENT_ID` | 本次安全策略操作目标，与测试逻辑 Agent 对齐 |
| `BIANBU_SEC_UDS` | 当前服务真实 socket |
| `BNSEC_AUDIT_DB` | 当前服务主审计库；不是 syscall/network 数据库 |
| `BNSEC_SECURITY_WEBUI_BASE` | 实际 WebUI URL/端口 |
| `BNSEC_OUT` | 本次独立证据目录，避免覆盖上一轮 |

通过 testkit 的正常配置和身份流程验证，不在终端伪造 lease/cgroup。涉及策略切换的测试使用专用 Agent，保存原值并在结束/异常时恢复。

## 5. 人工必须会做的验收

| 场景 | 操作思路 | 合格标准 |
|---|---|---|
| 基础聊天 | 新建会话，发无害问题 | Run 完成，有非空输出，关联到正确 Agent |
| normal 拒绝 | 专用 Agent 撤销无害探针需要的能力 | 目标工具执行次数为 0，错误可读，有匹配审计 |
| normal 确认 | 给探针工具设置确认条件 | 未批准执行次数为 0；批准恢复的正是该操作 |
| DLP block/mask | 用人工构造的假敏感样本测试输入、历史、工具结果和输出 | block 不外发；mask 出口无样本原文，有策略证据 |
| YOLO→normal | 保存策略/用量，切模式并恢复 | YOLO 行为符合第 4 篇；normal 原授权/预算恢复，累计用量保留 |
| 网络 | allow_all/whitelist/deny_all/learning 使用测试域名 | 保存值与实际连接结果吻合；观测场景有实际事件 |
| syscall | 用已审批的无害内核探针 | 指定拒绝 syscall 返回预期 errno；允许 syscall 成功；事件链有效 |
| 重启恢复 | 维护窗口重启相关服务 | 新 Worker/lease 可执行；旧身份不可复用；配置数据保留 |

网络失败要区分 DNS、provider 超时、内核拒绝与策略未应用。syscall 探针只能按目标架构编号使用既有测试方案，不用破坏性系统操作做“演示”。

## 6. 历史证据如何使用

历史通过报告证明特定日期和版本的行为。它不等于本次 HEAD 的全量回归。引用报告时同时给出版本、设备、命令/范围、结果和证据路径；“服务 active”不能替代审计事件数，“0 failed”也不能掩盖 0 collected 或 skipped。

最新可追溯结果索引在[当前状态](08-当前状态与遗留事项.md)。原始失败、环境修复后重跑和最终结果都保留，不能为了交接好看只抄最后一个数字。

## 7. 发布与后续产品化测试

Security 证据入口是 `impl/bianbu-securityd/.ci/run_tests.sh`，由 `BNSEC_SOURCE_REVISION`、`BNSEC_EVIDENCE_DIR`、`BNSEC_PYTHON`、`BNSEC_CVE_SCANNER` 等指定本轮配置。解释器和扫描器使用本轮准备的环境，不复制旧报告中的临时 venv 名。

发布证据应包含 `SECURITY_RELEASE_GATE_PASS` 和 `security_scope_status=passed`。组织级商用验收另外有 24/72h 耐久、CA、桌面、渗透和签名审批门禁；这些入口已存在，但是否列入下一阶段产品交付需确认范围。

如果启动 72h 测试，需独立排期并实际等到完成，不能把短稳样本改标签当长期证据。本次文档编写未运行发布、耐久或商用门禁。
